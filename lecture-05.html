第 5 讲 GPUs

预计用时： 120-180 分钟

一句话： 这一讲把 GPU “去魔法”：它为什么快、为什么有时又很慢，以及六个让它变快的通用技巧。终点是用这些技巧拆解 FlashAttention。它是 L06 写 kernel 的概念基础。

提示： 难度：纯概念、不吃 GPU，是理解后面所有系统课的地基。强烈建议零基础认真过——它把 L02 的 memory-bound、L06 的 kernel 都串了起来。

前置知识：这一讲默认你已经会（我从 0 给你补）

这一讲讲 GPU 硬件，默认你有一点计算机体系结构的常识。从 0 补上最关键的：

  • CPU / 内存 / 缓存的关系：CPU 是”计算的大脑”，内存(RAM)是”放数据的仓库”，缓存(cache)是”离 CPU 很近的小快仓”。规律贯穿全讲：离计算单元越近的存储越快、但越小越贵（寄存器 > 缓存/共享内存 > 主存/显存）。
  • 并行 vs 串行：串行 = 一件一件做；并行 = 很多件同时做。GPU 的全部威力来自”几千个小单元同时算”。
  • 延迟 vs 吞吐 (latency vs throughput)：延迟 = 单件事多快做完；吞吐 = 单位时间总共做完多少。CPU 优化延迟，GPU 优化吞吐——这是本讲第一个对比。
  • bit / byte / 浮点数：数据的最小单位。不熟的话见 第 0 讲 和 L02 的精度部分。
  • memory-bound / compute-bound 与 roofline：本讲反复用，但它其实是 L02 教过的——一个操作是被”搬数据的带宽”卡住还是被”算力”卡住。强烈建议先把 L02 的 arithmetic intensity 弄懂，这一讲是它的硬件细节版。

先补几个词（零基础向）

  • CPU vs GPU：CPU 像几个聪明的全能工人（优化”单件做得快”=延迟）；GPU 像成千上万个只会干简单活的小工（优化”总产量”=吞吐）。
  • ALU：算术逻辑单元，最基础的”计算小工”。GPU 有海量 ALU。
  • SM / SP：SM(流多处理器) 是 GPU 里一个个大车间，里面有很多 SP(小处理器) 跑线程。一块 GPU 有上百个 SM。
  • SRAM vs DRAM：SRAM = 离计算近的快内存（shared memory/cache，贵、小、快）；DRAM = 远的全局显存(HBM，便宜、大、慢)。差约 8 倍速度、100 倍价格。
  • SIMT：所有线程”同一条指令、不同数据”地一起跑。
  • tensor core（张量核心）：专门算矩阵乘的特化电路，比普通浮点运算快 10 倍以上。
  • roofline（屋顶线模型）：判断一个操作卡在算力还是带宽的图（见 L02）。
  • burst mode（突发读取）：DRAM 一次读会连带读出一大片相邻字节。

学完你能

  1. 理解 GPU 与 CPU 的设计哲学差异，以及 GPU 的执行/内存模型（thread/block/warp、register/shared/global）。
  2. 理解”算力增长快于内存增长”这个根本矛盾（memory wall）。
  3. 掌握 6 个加速技巧：控制分支、低精度、算子融合、重计算、内存合并、tiling。
  4. 用这些技巧理解 FlashAttention 为什么快。

GPU 的设计哲学：为吞吐而生

  • CPU：少量快线程，优化延迟（每个线程尽快完成），有复杂的分支预测和缓存。
  • GPU：海量轻量线程，优化吞吐（单位时间处理的总数据量），分支支持弱。
  • 三层执行模型：thread（干活）→ block（一组线程，跑在一个 SM 上、共享 shared memory）→ warp（32 个连号线程，步调一致一起跑）。
  • 三层内存：register（每线程私有，最快）→ shared memory（block 内共享，快）→ global memory/HBM（跨 block 才用，慢）。

根本矛盾：内存墙 (memory wall)

算力(FLOPs)的增长速度远快于内存带宽的增长速度。 tensor core 让矩阵乘快了 10 倍以上，但把数据喂给它的带宽没跟上。结果：大多数时候 GPU 在等数据，而不是在算。这就是 L02 说的 memory-bound，也是本讲所有优化的总动机——尊重内存层级、少碰慢内存(HBM)。

六个加速技巧

技巧 思路 省的是什么
① 控制分支 (control divergence) 同 warp 别走不同 if 分支 避免分支串行化的开销（非内存问题）
② 低精度 (low precision) 用更少的位（bf16/fp8/fp4） 位少→搬得少→算术强度更高；还能用 tensor core
③ 算子融合 (fusion) 多个操作合成一个 kernel 避免反复读写 HBM
④ 重计算 (recomputation) 反向时丢弃激活、用时重算 用算力换显存
⑤ 内存合并 (coalescing) 同 warp 访问连续地址 让一次 burst 喂满 32 个线程
⑥ Tiling（分块） 把矩阵切块塞进 shared memory 复用 大幅减少 HBM 访问（最重要）

融合的直觉（工厂比喻）：GPU 像工厂，数据从仓库(HBM)运来。算 sin²x+cos²x 朴素写法要启动 5 个 kernel、来回搬 5 趟；融合成 1 个 kernel，搬 1 趟就全算完。torch.compile 能自动做这种简单融合。

Tiling 的数学：不分块时，矩阵乘每个输入要从 HBM 读 N 次；分块（tile 大小 T）后，每个输入只从 HBM 读 N/T 次（其余 T 次在快的 shared memory 里复用）→ HBM 访问减少 T 倍。这就是 L06 matmul kernel 的核心，也是把算术强度从 O(1) 提到 O(T) 的手段。

一个要小心的坑——wave quantization：tile 数若不能整除 SM 数，最后一波有 SM 空闲。例：A100 有 108 个 SM，矩阵从 1792 涨到 1793，tile 数从 98 跳到 120 > 108，得跑两波 → 性能突然变差。“大矩阵更快”背后有这种台阶效应。

终点：FlashAttention 为什么快

注意力 = 三个矩阵乘(Q/K/V) 中间夹一个 softmax。朴素实现要把巨大的 n×n 注意力矩阵写回 HBM 再读回来，极其费带宽。FlashAttention 的两招： 1. 对 QKV 矩阵乘做 tiling（把上面学的 tiling 用上）。 2. 在线 softmax (online softmax)：softmax 需要整行做归一化，但分块后一次只看到一块。技巧是增量地维护当前最大值，用一个”伸缩求和”逐块更新，于是 softmax 也能分块算，不必把整个注意力矩阵落地到 HBM。 3. 顺手融合 exp 运算。

结果：注意力的中间大矩阵从不写回 HBM，全在快内存里算完 → 大幅提速、还省显存。这是”tiling + fusion + 在线算法”的集大成，也是 A2 要你实现的东西。
