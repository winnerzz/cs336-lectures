第 17 讲 Multimodal (多模态)

预计用时： 90-150 分钟

一句话： 前 16 讲都是”文本→文本”。但世界是多模态的。这一讲（全课最后一讲）讲怎么让 Transformer 处理图像/视频/音频：核心难题是把非文本也变成 token。讲 CLIP/SigLIP（编码图像）、LLaVA/Qwen-VL（接进 LLM）、Chameleon（统一生成）。

提示： 难度：概念为主、不吃 GPU，好读，是个漂亮的收尾。

前置知识：这一讲默认你已经会（我从 0 给你补）

这一讲默认你懂一点视觉模型术语。从 0 补上：

  • 模态 (modality)：信息的种类——文本、图像、音频、视频各是一种模态。“多模态”= 同时处理多种。“omni 模型”= 任意模态输入、任意模态输出的终极目标。
  • 为什么要”变成 token”：Transformer 只会处理 token 序列（见 L01 对文本的分词）。所以图像也得想办法切成一串 token 喂进去。这是全讲的主线难题。
  • 图像编码器 (image encoder)：把一张图变成一串向量的网络。常用 ViT (Vision Transformer)：把图切成一个个小方块(patch，如 14×14 像素)，每个 patch 当一个 token，过 Transformer。
  • 对比学习 (contrastive learning)：训练时让”配对的(图,文)“互相靠近、”不配对的”推远，从而学出”图和文对齐”的表示。CLIP 用的就是这个。
  • 嵌入空间 (embedding space)：把不同东西映射到同一个向量空间，相近=语义相近。多模态就是想让”图的向量”和”文的向量”落在可比较的空间里。
  • diffusion / VQ-VAE（生成图像用，正文简述）：把图压成离散 token、再解码回图的两类技术。

全讲两个问题

① 怎么输入非文本（让模型看懂图）？ ② 怎么输出非文本（让模型生成图/音）？ 当下答案：把一切都转成 token，喂给 Transformer。

一张图到底变多少 token（接 L02/L10 的序列账）

主线难题是”图像→token”，先把数量算出来，才知道它对序列长度有多大冲击。ViT 把图切成 P×P 的 patch，每个 patch = 一个 token：

token 数 = (高/P) × (宽/P)
224×224 图、patch=14 → (224/14)² = 16² = 256 个 token
512×512 图、patch=14 → (512/14)² ≈ 36² ≈ 1340 个 token
高分辨率/多图/视频 → 轻松上万 token

这就把多模态接回了前面的账本：图像 token 和文本 token 挤在同一个上下文里，L02 的注意力 seq² 开销、L10 的 KV cache 全都按这个加大的 seq 算。所以”一张高清图顶上千 token”是 VLM 又慢又吃显存的根源——Qwen-VL 的 AnyRes、token 合并等技巧本质都是在压这个 token 数。

编码图像：CLIP 与 SigLIP

CLIP（对比式图文预训练）：拿海量(图, 文字描述)对，分别编码图和文，训练目标是让配对的图文互相偏好、不配对的推远（一个 batch 里做对比）。结果：学出了”懂语义”的图像编码器，零样本就能在 ImageNet 上超过专门训练的 ResNet。数据：4 亿图文对。

“对比”到底怎么算（一个 batch 内的相似度矩阵）：取一个 B 对图文的 batch，编码成 B 个图向量、B 个文向量，两两算相似度得到一个 B×B 矩阵 S，S[i][j] = 第 i 张图和第 j 段文的相似度：

       文0   文1   文2
图0  [ ✓    ·     ·  ]      对角线 (i=i) 是真实配对 → 要最大
图1  [ ·    ✓     ·  ]      非对角 = batch 里其他图文 → 当负例，要最小
图2  [ ·    ·     ✓  ]

损失 = 对每一行做 softmax 分类（“这张图该配哪段文”，正确答案是对角线）+ 对每一列同样做一遍，两个交叉熵取平均。关键洞见：负例是”白来的”——同 batch 里其他 B−1 个样本天然就是负例，所以 batch 越大、负例越多、学得越好（CLIP 用了上万的大 batch）。这也是下面 SigLIP 要解决的痛点。

SigLIP：把 CLIP 的”在整个 batch 上做 softmax 多分类”换成逐对的 sigmoid 二分类（这对图文配不配？）。好处：和 batch 大小解耦、更省、小 batch 也好。

把图像编码接进 LLM：LLaVA 与 Qwen-VL

标准 VLM(视觉语言模型)模板：视觉编码器 + 投影层(projector) + 语言模型。即：用 CLIP/SigLIP 把图编码成向量，过一个小投影层映射到 LLM 的词嵌入空间，当成”几个 token”插进文本里，让 LLM 一起处理。

  • LLaVA：CLIP(视觉) + Vicuna(语言)，中间一个线性投影。用 GPT-4 把图片标注合成成问答对当训练数据。两阶段训练：先只训投影层（对齐），再训投影+语言模型（微调）。
  • LLaVA-OneVision / Qwen-VL 系列：处理高分辨率（AnyRes：把大图切块分别编码再拼）、多图、视频；动态分辨率；多模态旋转位置编码(MRoPE)。训练通常分阶段：先训视觉编码器/投影，再放开全部参数，最后指令微调。
  • 共同点：大部分功夫花在数据整理上（大量合成、任务特定数据），架构改动是次要但有用的。

走向 Omni：Chameleon（统一生成）

上面的 VLM 能”看”图但不能生成图（要另配 diffusion）。Chameleon 的思路：把图像也变成离散 token，和文本 token 放一起做统一的自回归建模——这样看图和生成图就统一了。

关键技术 VQ-VAE：把图像编码到一个离散码本（如 8192 个码），再解码回图、最小化重建误差；于是一张 512×512 图就变成 1024 个”图像 token”，甚至能给它训一个 BPE。

代价：离散化有损（OCR 这种细节会丢）、性能不如专门方案；而且文本 token 熵低、图像 token 熵高，混训不稳定（要用 L03 的 QK-norm、z-loss 来稳）。

全课收尾

  • 前沿模型默认是原生多模态(omni)。
  • 根本难题始终是：怎么把非文本模态编码成 token。
  • 理解(看懂)和生成(画出)需求不同：理解要语义，生成要细节。
  • 用连续编码器 + Transformer + diffusion 做生成是当前主流；Chameleon 式纯离散自回归更优雅但更难。
