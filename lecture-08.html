第 8 讲 Parallelism Basics (进阶)

预计用时： 120-180 分钟

一句话： L07 介绍了三种并行的基本概念，这一讲深入”工业级”做法：用 ZeRO/FSDP 把数据并行的显存浪费榨干，再把张量/流水线/序列/专家并行组合成 3D 并行来训真正的大模型。

提示： 难度：偏系统、信息密集，对应 A2，需多 GPU。先读 L07 笔记再看这份。零基础目标：看懂”为什么要分片、各种并行怎么组合”，记不住所有数字没关系。

前置知识：这一讲默认你已经会（我从 0 给你补）

这一讲是 L07 的深化，几乎所有前置都在 L07 和 L02 里。从 0 补上/指路：

  • 集合通信原语（all-reduce / reduce-scatter / all-gather）：本讲的地基，尤其 all-reduce = reduce-scatter + all-gather 这条等式。先看 L07 笔记 把这几个动作弄懂，否则 ZeRO 看不动。
  • 三种并行（数据/张量/流水线）的基本概念也在 L07；这一讲讲它们的工业级组合。
  • 每个参数为什么占 16 字节（参数+梯度+优化器状态）：这是 L02 的训练显存账。ZeRO 的全部意义就是”把这 16 字节里重复存的部分分片”，所以 L02 那块必须先懂。
  • 进程 / 带宽 / 网络层级：见 L07 前置板块。

先补几个词（零基础向，其余见 L07 笔记）

  • DDP (Distributed Data Parallel)：最朴素的数据并行——每块 GPU 存整个模型，各算各的梯度，再 all-reduce 同步。
  • ZeRO / FSDP：数据并行的省显存升级版。把”每块都存一份”的东西（优化器状态/梯度/参数）分片到各 GPU，用时再临时凑齐。FSDP = ZeRO stage 3。
  • 模型并行 (model parallelism)：把模型本身切开放到不同 GPU（区别于数据并行的”模型整份复制、切数据”）。包括流水线/张量/专家并行。
  • 激活 (activation) 显存：前向中间结果占的显存，随 batch、序列长度涨，常被忽略却很大。
  • 3D/4D 并行：同时叠加多种并行（数据+张量+流水线+…）。
  • bubble（气泡）：流水线里 GPU 空等的时间。

学完你能

  1. 看清朴素数据并行的显存浪费（每参数要 16 字节、5 份拷贝）。
  2. 理解 ZeRO 三级如何逐步分片优化器状态/梯度/参数，几乎”免费”省显存。
  3. 理解模型并行：流水线（切深度）、张量（切宽度）、序列（切长度）、专家（切专家）。
  4. 掌握”3D 并行”的组合规则（先 TP/EP 填满单机、PP 跨机、剩下 DP）。

朴素数据并行的显存有多浪费

每块 GPU 都存完整模型。用 Adam + 混合精度时，每个参数要占 16 字节：

项 字节 说明
参数 (bf16) 2
梯度 (bf16) 2
主权重 (fp32) 4 SGD 累加用的”master copy”
Adam 一阶矩 (fp32) 4
Adam 二阶矩 (fp32) 4

问题：这 16 字节里，绝大部分（优化器状态）在每块 GPU 上都是重复存的。8 块 GPU 就重复 8 份。ZeRO 的核心洞见：这些重复完全没必要。

ZeRO：把重复的东西分片（基于那条等式）

利用 L07 的 all-reduce = reduce-scatter + all-gather，逐级分片：

级别 分片什么 通信代价 效果
ZeRO-1 优化器状态 2×参数（和 DDP 一样） 白送的省显存，应该总是开
ZeRO-2 + 梯度 2×参数（几乎一样） 几乎白送
ZeRO-3 (FSDP) + 参数本身 3×参数（1.5 倍） 显存大降，通信略增

ZeRO-3 (FSDP) 怎么工作？ 参数也分片存。前向走到某层时，临时 all-gather 把这层的完整参数凑齐、算完立刻丢掉；反向同理，梯度算完 reduce-scatter 发回负责的 GPU。关键优化：让 all-gather 和计算重叠（一边算这层、一边偷偷把下层参数拉过来），把通信开销藏起来。代价只有 1.5 倍通信，换来显存近乎线性下降。

实测（8×A100-80G，每参数约 12 字节）：朴素 ~6.6B，ZeRO-1 16B，ZeRO-2 24B，ZeRO-3 53B。分片越多，能训的模型越大。

数据并行的天花板

  • batch 限制：数据并行的机器数不能超过 batch 大小，且 batch 太大收益递减。
  • 激活显存：ZeRO 省的是参数/梯度/状态，激活显存它不管。模型再大、激活放不下，就得动模型本身 → 模型并行。

模型并行：切模型的三种刀法

方式 切的维度 通信 适合
流水线并行 (PP) 深度（层） 层间传激活，点对点，量小；但有 bubble 慢网络（跨机器）
张量并行 (TP) 宽度（每层的矩阵） 每层 all-reduce 激活，量大 快网络（单机 NVLink，≤8 卡）
序列并行 (SP) 长度（序列） 配合 TP，分摊 LayerNorm/Dropout 的激活 和 TP 搭配
专家并行 (EP) 专家（MoE） token 路由的 all-to-all MoE 模型

流水线的 bubble 与 micro-batch：把层分给 n 块 GPU，朴素做法每块只有 1/n 时间在干活（其余在等）。解法是把 batch 切成多个 micro-batch 像流水线一样喂，bubble 占比 ≈ (n_stages−1)/n_micro，所以需要足够大的 batch / 足够多的 micro-batch 才划算。

张量并行为什么 ≤8 卡：它每层都要 all-reduce 激活，通信极频繁，只有单机内的 NVLink 才扛得住。超过一台机器（8 卡）通信就成瓶颈。

序列并行补的是什么洞：TP 切了矩阵乘部分，但 LayerNorm/Dropout 这些逐元素操作的激活仍随规模涨。SP 把它们沿序列维切开，让激活显存也能线性下降。

3D 并行：把它们叠起来

真实大模型训练同时用好几种。经验法则（rule of thumb）：

  1. 先让模型塞进显存：单机内用张量/专家并行（≤8 卡）；跨机器用流水线并行（或 ZeRO-3，看带宽）。
  2. 再用满所有 GPU：剩下的规模用数据并行扩展。
  3. batch 小的话，用梯度累积换更大的有效 batch、提高通信效率。

实例：Llama3-405B 用 DP=128 / TP=8 / PP=16；DeepSeek v3 用 EP=64 / PP=16 / ZeRO-1。规律：TP 一般 ≤8，EP 可以很大（但难），长上下文阶段用大 CP（上下文并行）。

思考练习

  1. 朴素数据并行每参数要 16 字节，其中哪些是”每块 GPU 重复存”的？ZeRO 先拿哪部分开刀？
  2. 为什么说 ZeRO-1 是”应该总是开”的？（提示：通信代价对比 DDP）
  3. 你有 64 块 GPU（8 机 ×8 卡）。按经验法则，张量并行该设多少？为什么不跨机器？
  4. 流水线并行的 bubble 占比公式说明了什么？为什么需要大 batch？
