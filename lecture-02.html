CS336 学习台

第 2 讲 Resource Accounting

预计用时： 120-180 分钟

一句话： 在固定的算力和显存下，要训出最好的模型，前提是你能准确算出一段计算花了多少 FLOPs、占了多少显存。这一讲不讲 ML 魔法，只教你像工程师一样”算账”。

前置知识：这一讲默认你已经会（我从 0 给你补）

CS336 默认你上过类似 CS224N（深度学习/NLP 入门）的课，所以它不会重新解释下面这些。但你基础偏弱，所以我先把这一讲真正依赖的几块从 0 补上。Python/字节这些更底层的，见 第 0 讲 · 基础搭建。

① 矩阵乘法的”维度规则”（全课最常用） 两个矩阵相乘 A @ B，要求 A 的列数 = B 的行数，结果形状是”A 的行 × B 的列”：

(B, D) @ (D, K) -> (B, K)     # 中间的 D 必须相等，会被"消掉"

直觉：把 (B, D) 看成”B 条数据、每条 D 个特征”，乘一个 (D, K) 的权重，就把每条数据从 D 维变成 K 维。神经网络的每一层基本都是这种乘法。本讲数 FLOPs、算显存，全建立在”看得懂形状怎么变”上。

② “训练一个模型”到底在干嘛（机制，不是玄学） 训练就是不停重复这 4 步的循环：

1. 前向(forward) ：把数据喂进模型，算出预测，和正确答案比，得到误差 loss
2. 反向(backward)：反推每个参数"该往哪个方向调"才能让 loss 变小（这个方向叫梯度）
3. 更新(step)    ：优化器(如 Adam)按梯度把每个参数挪一小步
4. 清零→回到 1，换下一批数据

模型就是一大堆数字(参数)。训练 = 反复微调这些数字，让 loss 越来越小。本讲算的”显存四块去向(参数/梯度/优化器状态/激活)“就对应这 4 步里要存的东西。

③ 梯度/求导的直觉（不用会算，只要懂含义） “导数”就是斜率：参数往某方向动一点点，loss 会变大还是变小、变多快。“梯度”就是所有参数的斜率合在一起，指向”loss 上升最快的方向”——所以训练时朝反方向走，loss 就下降。你不需要会手算导数，PyTorch 的 loss.backward() 自动帮你算。

④ PyTorch 是什么 一个 Python 库，专门高效地做”张量(tensor)运算 + 自动求梯度 + 用 GPU 加速”。本讲的代码片段都是 PyTorch。tensor 就是”成堆的数字”，详见下面的速查和 第 0 讲。

先补几个词（零基础向，看正文前先扫一遍）

这一讲会反复用到下面这些词。先用大白话过一遍，正文就不卡了。

  • tensor（张量）：就是一堆排好格子的数字。一个数字是 0 维；一排数字（向量）是 1 维；一张表格（矩阵）是 2 维；再叠厚一点就是 3 维、4 维。深度学习里，数据、模型参数、中间结果全都是 tensor。“rank/维数”就是它有几层格子。
  • 参数 (parameters)：模型里要学习的数字，就是那些权重。GPT 有几十亿个参数 = 几十亿个待定的数。
  • 浮点数 (floating point)：计算机表示带小数的数的方式。它用固定的二进制位（bit）来存，位越多越精确但越占地方。后面 fp32/bf16 就是”用多少位存一个数”的不同方案。
  • FLOP：一次最基本的浮点运算，比如一次加法或一次乘法。数 FLOPs = 数这段计算一共做了多少次加减乘。
  • matmul（矩阵乘法）：两个表格相乘。它是神经网络里最耗算力的操作，记住这个词。
  • 显存 (GPU memory)：显卡上的内存，单位字节(byte)。tensor 都要放在这里才能被 GPU 计算。显存不够 = 模型训不起来，这是自学者最常撞的墙。
  • 带宽 (bandwidth)：数据在”显存”和”计算核心”之间搬运的速度，单位字节/秒。可以想成一条水管的粗细：核心算得再快，水管细也会被卡住。
  • 前向 / 反向 (forward / backward)：前向 = 把输入喂进模型算出预测和误差(loss)；反向 = 反着推一遍，算出”每个参数该往哪个方向调”（这个方向叫梯度 gradient）。反向传播是神经网络能”学习”的核心机制，这里只需知道它存在、比前向贵。
  • 优化器 (optimizer)：拿着梯度去真正更新参数的算法（如 SGD、Adam）。有些优化器（Adam）还要额外记一些历史信息，叫”优化器状态”，也占显存。
  • 激活 (activation)：前向过程中每一层算出来的中间结果。反向传播需要用到它们，所以训练时得把它们存着——这是训练比推理更吃显存的主要原因。
  • batch / sequence length：batch = 一次喂多少条样本；sequence length = 每条样本有多长（多少个 token）。这两个越大，激活越多，越吃显存。

不用背。看正文时哪个词卡住了，回到这里瞄一眼即可。

学完你能

  1. 学会用”餐巾纸估算”(napkin math) 快速判断一次训练要多久、最大能训多大的模型。
  2. 掌握显存会计：tensor 占多少字节、不同精度格式的取舍。
  3. 掌握计算会计：matmul 的 FLOPs 怎么数、什么是 MFU。
  4. 理解 arithmetic intensity / roofline：一个操作是被算力卡住(compute-bound) 还是被带宽卡住(memory-bound)。
  5. 把这些串到训练上：参数、梯度、激活、优化器状态各占多少；为什么一步训练约是 6 × 数据量 × 参数量 FLOPs。

开场两个”算账”例子（先建立直觉）

例 1：70B 模型、15T tokens、1024 张 H100，要训多久？

先解释符号：70B = 700 亿参数（B=billion）；15T tokens = 15 万亿个 token（T=trillion）；H100 是一款常见的训练显卡。e 是科学计数法，70e9 就是 70×10⁹。

总 FLOPs = 6 × 70e9 (参数) × 15e12 (tokens)
H100 算力 ≈ 1979e12 / 2  FLOP/s   (bf16 稠密，约每秒 1e15 次运算)
MFU ≈ 0.5                         (实际利用率打个对折，见下文)
每天 FLOPs = 算力 × MFU × 1024 张 × 86400 秒
天数 = 总FLOPs / 每天FLOPs

记住 6 × 参数量 × token数 这个公式——它是整个 scaling 讨论的地基。直觉：训练总成本 ≈ 参数越多、看的数据越多，就越贵，且是简单的相乘关系。

例 2：8 张 H100、用 AdamW，最大能训多大模型？

每张 H100 显存 ≈ 80e9 字节 (80 GB)
每个参数占字节 = 2(参数本身) + 2(它的梯度) + (4+4)(Adam 的两个状态) = 12 字节
最大参数量 = (80e9 × 8) / 12

为什么一个参数要占 12 字节？因为训练时，每个参数身上挂着一串东西：它自己(2B) + 反向算出的梯度(2B) + Adam 记的两份历史(各 4B)。下文”训练显存账”会展开。

注意：这没算激活(activation)，所以是上界（实际能训的更小）。

这两个估算不精确，但”信封背面”算一下，你就对资源消耗有了量级感。这就是本讲要培养的 mindset。

一切都是 tensor

数据、参数、梯度、优化器状态、激活——全是 tensor（成堆的数字）。Transformer 里常见 4 维 tensor：(batch, seq, heads, head_dim)，可以读成”一批样本 × 每条多长 × 多少个注意力头 × 每个头多宽”。

显存 = 元素个数 × 每个元素字节数

一个公式就够：显存 = 数字个数 × 每个数字占几字节，代码里是 x.numel() × x.element_size()。

不同精度格式就是”一个数字用几个字节存”的取舍：

精度 字节 关键特点（大白话）
fp32 4 默认、最精确，但最费显存
fp16 2 省一半显存，但能表示的数范围窄：太小的数（如 1e-8）会被当成 0（叫”下溢”），训练容易崩
bf16 2 同样省一半，但能表示的范围和 fp32 一样大，只是小数精度差点——而深度学习不在乎那点精度。所以 bf16 是训练首选
fp8 1 更省，H100 才支持
fp4 0.5 2025 年的极限玩法，每”块”配一个缩放系数来补救范围

为什么 bf16 比 fp16 好？ 一个浮点数的位分两部分：一部分管”能多大多小”(指数/范围)，一部分管”小数有多准”(精度)。fp16 把位更多分给精度，结果范围太窄、小数会下溢到 0；bf16 反过来，保住范围、牺牲精度。训练里”别下溢崩掉”比”多几位小数”重要得多，所以选 bf16。

混合精度训练 (mixed precision) 是标准做法，也是为了兼顾”省显存”和”别崩”： - 参数 / 激活 / 梯度 用 bf16（省显存） - 优化器状态 用 fp32（要在成百上千步上累加平均，需要更稳） - PyTorch 的 AMP (torch.amp.autocast) 会自动判断：能安全用 bf16 的地方（如 matmul）就用，危险的地方（如 exp 指数运算）保留 fp32。

tensor 默认在 CPU 内存，要 .to(device) 搬到 GPU 才能用上 GPU 的大规模并行。

直觉：GPU 像一个有上千个小工人的车间，但原料(tensor)得先运进车间(显存)，工人才能开工。

einops：给维度起名字，别再数 -1/-2

传统 PyTorch 写法 x @ y.transpose(-2, -1) 很容易搞错是哪两维在动。einops 让你用名字写，自解释：

einsum(x, y, "batch seq1 hidden, batch seq2 hidden -> batch seq1 seq2")
reduce(x, "... hidden -> ...", "sum")          # 把 hidden 这一维加掉
rearrange(x, "... (heads d) -> ... heads d", heads=2)   # 把一个大维拆成两维

记一条规则就行：箭头右边没出现的维度，会被自动求和(sum)掉。现在看不懂没关系，A1 写 Transformer 时会反复用到。

FLOPs 怎么数

  • FLOPs（小写 s）= 做了多少次浮点运算 = 工作量。
  • FLOP/s（带斜杠）= 硬件每秒能做多少 = 速度。两者读音一样，务必分清。
  • 一次矩阵乘 (B,D) @ (D,K) 的 FLOPs = 2 × B × D × K。

这个 2BDK 怎么来的？ 矩阵乘的结果是个 B×K 的表格，共 B×K 个格子。每个格子要把长度为 D 的两行做点积：D 次乘法 + D 次加法 ≈ 2D 次运算。所以总共 B×K×2D = 2BDK。记住”每个输出格子 ≈ 2D 次运算”就能自己推。

  • MFU (Model FLOPs Utilization) = 实际跑出的 FLOP/s ÷ 硬件理论峰值 FLOP/s，相当于“显卡的实际利用率”。≥ 0.5 就算很好。为什么到不了 100%？因为常被”搬数据”拖后腿——下一节解释。

Arithmetic Intensity 与 Roofline（本讲最重要的洞见）

做一次计算其实分三步：① 从显存把输入搬到计算核心 → ② 算 → ③ 把结果搬回显存。所以耗时取决于两件事：算力(FLOP/s) 和 带宽(bytes/s，搬运速度)。

  • 算术强度 (arithmetic intensity) = FLOPs ÷ 搬运的字节数：这个操作每搬 1 字节，能顺带干多少活。强度高 = 搬一次数据能算很久（划算）；强度低 = 搬半天只算一下（核心在空等）。
  • 硬件强度 (accelerator intensity) = 峰值FLOP/s ÷ 带宽：这块显卡”算力与水管”的固定比值，是个分界线。
  • 判断瓶颈：
    • 算术强度 < 硬件强度 → memory-bound（被带宽/搬运卡住，核心在等数据）
    • 算术强度 > 硬件强度 → compute-bound（被算力卡住，核心满负荷，理想状态）

实例（H100，bf16）：

操作 算术强度 瓶颈
ReLU（逐元素） ~1/4 memory-bound
GeLU（逐元素，算得多点） 略高 仍 memory-bound
点积 ~1/2 memory-bound
矩阵 × 向量 ~1 memory-bound
矩阵 × 矩阵（大矩阵） ~n/3 compute-bound ✓

结论（很重要）： - 逐元素操作几乎都是 memory-bound（所以 ReLU 并不比 GeLU 快——两者都卡在搬数据上，不在算上）。 - 只有大矩阵乘法才能喂饱算力。训练 Transformer 全是大 matmul → compute-bound（好事，钱花在刀刃上）。 - 推理 (inference) 主要是矩阵 × 向量 → memory-bound。这解释了一个常见现象：推理慢，往往不是算力不够，而是带宽不够。 - 一句话总结：MFU = min(1, 算术强度 / 硬件强度)。

训练时的显存与计算账（把上面都串起来）

对一个网络（参数量 N、batch B），训练时显存花在四个地方：

占用 大小 说明
参数 2N 模型本身（bf16，每个 2 字节）
梯度 2N 反向算出的”每个参数该怎么调”
优化器状态 AdaGrad 4N / Adam 8N Adam 给每个参数记两份历史（一阶+二阶矩，fp32 各 4 字节）
激活 2 × (B × D × L) 前向每层的中间结果，随 batch 和层数 L 上涨

计算账（每步训练）： - 前向：2 × 数据量 × 参数量 - 反向：4 × 数据量 × 参数量 - 合计：6 × 数据量 × 参数量

为什么反向是前向的 2 倍？ 反向时，每一层要算两个东西：一是”误差怎么传给上一层”(d_loss/d_输入)，二是”这层参数该怎么调”(d_loss/d_权重)。两个都各是一次和前向同量级的 matmul，所以 2 倍。前向 1 份 + 反向 2 份 = 3 份，每份的常数是 2BDK 里的 2 → 合起来就是著名的 6ND。

这对简单网络(MLP)精确，对短上下文的 Transformer 也是好近似。

两个省显存的技巧

  • 梯度累积 (gradient accumulation)：想用大 batch（更稳）但激活放不下 → 把大 batch 拆成几个小 micro-batch，逐个算梯度、累加但先不清零，攒够一个完整 batch 再统一更新参数。效果等同大 batch，但激活显存只按 micro-batch 算，省一大截。
  • 激活检查点 (activation checkpointing / 重计算)：前向时只存少数几层的激活，反向需要用到中间激活时，从最近的存档点临时重新算一遍。本质是”用多花点算力，换省下的显存”。常用折中：每隔 √L 层存一次，激活显存降到 O(√L)，多付 O(L) 的重算。

优化器谱系（顺手记，知道它们的区别即可）

momentum = SGD + 对梯度做”指数平均”（让更新更平滑） AdaGrad = SGD + 对 梯度² 做累加（给不同参数自适应的步长） RMSProp = AdaGrad，但 梯度² 用指数平均（更适合长训练） Adam = RMSProp + momentum（最常用，所以它要存两份状态 → 8N）
