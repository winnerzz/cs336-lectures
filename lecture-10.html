第 10 讲 Inference (推理)

预计用时： 120-180 分钟

一句话： 训练是一次性成本，推理是天天重复花钱。这一讲先讲清”推理为什么是 memory-bound、慢在哪”，再讲一整套加速手段：换更省 KV cache 的架构、量化、剪枝/蒸馏、投机采样、连续批处理/PagedAttention。

⚠️ 难度与期待：概念密集但不太吃 GPU，很多可以纯理解。这一讲比 06/07 更”读得动”，适合零基础认真过一遍建立全局观。

前置知识：这一讲默认你已经会（我从 0 给你补）

这一讲讲推理为什么慢，几乎全建立在前面两讲上。从 0 补上/指路：

  • memory-bound / compute-bound 与算术强度（最重要的前置）：本讲反复说”推理是 memory-bound”，这套判断就是 L02 的 arithmetic intensity——一个操作被”搬数据的带宽”卡住还是被”算力”卡住。先把 L02 这块弄懂，这一讲才有根。
  • 矩阵×矩阵 vs 矩阵×向量：训练是大”矩阵×矩阵”(compute-bound、快)，推理生成是”矩阵×向量”(memory-bound、慢)。为什么后者吃亏，见 L02 的算术强度表。
  • 注意力 / Q·K·V / KV：本讲的 KV cache、GQA、MLA 都在改注意力的零件。不熟的话看 L03 前置板块。
  • 自回归生成 (autoregressive)：模型一个 token 一个 token 地生成，每生成一个就把它接到输入末尾、再生成下一个。这个”只能顺序、没法并行”正是推理慢的根源。
  • token / 概率分布：见 L01。模型每步输出”下一个 token 的概率”，采一个出来。

先补几个词（零基础向）

  • 推理 (inference)：模型训练好之后，拿来用（聊天、补全、跑评测、强化学习采样）的过程。
  • token：模型处理文本的最小单位（约等于一个词或词片）。模型是一个 token 一个 token 地生成的。
  • prefill（预填充）vs generation（生成）：推理分两阶段。prefill = 把你的整段提示词一次性读进去（可并行，快）；generation = 一个一个吐新 token（只能顺序来，慢）。
  • KV cache：生成下一个 token 时，前面所有 token 的中间结果（Key、Value 向量）存起来复用，避免每步从头重算。它存在显存里，是推理显存的大头。
  • latency（延迟）vs throughput（吞吐）：延迟 = 单个请求出 token 多快（在意体验时关键）；吞吐 = 单位时间所有请求总共出多少 token（批处理时关键）。两者常常此消彼长。
  • TTFT (time-to-first-token)：用户从发问到看到第一个字的等待时间，基本由 prefill 决定。
  • quantization（量化）：用更少的位存数字（bf16→int8→int4），省显存换速度，代价是精度。
  • distillation（蒸馏）：用大模型当老师，教一个小模型，让小模型又快又不太掉点。

主线还是 L02 那套：推理是”矩阵×向量”为主 → memory-bound → 瓶颈在搬数据(读参数和 KV cache)。所以几乎所有加速手段，本质都是”少读点东西”。

学完你能

  1. 理解推理 workload 的特点：两阶段(prefill/generation)、为什么 generation 是 memory-bound。
  2. 算清 MLP 层和 attention 层的算术强度，理解”为什么 batch 大对 MLP 有用、对 attention 没用”。
  3. 掌握降 KV cache 的架构：GQA、MLA、CLA、局部注意力。
  4. 了解量化、剪枝/蒸馏、投机采样、连续批处理/PagedAttention。

为什么推理和训练如此不同

  • 训练：所有 token 同时可见，能在序列维度上并行 → 全是大 matmul → compute-bound（喂得饱算力）。
  • 推理的 generation：必须一个一个生成，没法在”还没生成的 token”上并行 → 退化成矩阵×向量 → memory-bound（算力空等数据）。

这就是推理优化的总根源：算力其实够，卡在”每生成一个 token 都要把全部参数 + KV cache 从显存读一遍”。

KV cache：救星，也是新瓶颈

朴素生成：每出一个 token，都把全部历史重新喂进 Transformer → 生成 T 个 token 要 O(T³) FLOPs，巨亏。

解法：把每个 token 在每层每个 head 算出的 Key/Value 向量缓存到显存(KV cache)，下一步直接复用。代价是 KV cache 占显存，且随 batch、序列长度、层数线性增长——于是它成了新的显存瓶颈。后面一半内容都在想办法缩小 KV cache。

算术强度：batch 为什么对 MLP 有用、对 attention 没用

讲义对两类层做了 FLOPs/字节会计（沿用 L02 方法），结论（B=batch, S=历史长度, T=生成长度）：

层 prefill (T=S) generation (T=1)
MLP 强度 ≈ B·S（够大就 compute-bound，好） 强度 ≈ B（靠堆并发请求才能救）
attention 强度 ≈ S/2（好） 强度 < 1（没救，永远 memory-bound）

为什么加大 batch 对 attention 没用？ MLP 层里所有序列共用同一套权重(Wup/Wgate/Wdown)，batch 越大，读一次权重就能服务越多序列 → 摊薄了搬运成本。但 attention 里每条序列有自己独立的 KV cache，batch 翻倍，要读的 KV 也翻倍 → 占不到便宜。所以 attention 的 generation 是硬骨头。

一句话总结：prefill 是 compute-bound（好办），generation 是 memory-bound（难办，尤其 attention）。

延迟 vs 吞吐的权衡

以 Llama2-13B 在 H100 为例，加大 batch： - 延迟变差：KV cache 变大(O(B))，每步要读的更多。 - 吞吐变好：读一次参数能服务更多请求，摊薄成本。 - batch 太大还会爆显存，且吞吐收益递减。

实操：prefill 用小 batch（降 TTFT），generation 用大 batch（提吞吐）。最简单的扩展：开 M 份模型副本，延迟不变、吞吐 ×M。

降 KV cache 的架构（有损但通常不掉点）

方法 思路 一句话
GQA（分组查询注意力） N 个 query head 共享 K 个 KV head KV cache 缩小 N/K 倍，几乎不掉精度，已是标配
MLA（多头潜在注意力） KV 压成一个低维向量存，用时再投影回去 DeepSeek 把 16384 维压到 512，甚至比 MHA 还略好
CLA（跨层注意力） 让相邻层之间共享 KV 类比 GQA 但跨的是层
局部注意力（滑动窗口） 每个 token 只看附近一段 KV cache 不随序列长度涨；常和全局注意力混用以保精度

共同点：推理是 memory-bound，KV cache 越小越快。这些都是在”省 KV cache”和”别掉精度”之间找帕累托最优。

其它加速手段（了解）

  • 量化 (quantization)：bf16→fp8→int8→int4，位越少越省显存越快，精度风险越大。分训练时量化(QAT，贵但准) 和训练后量化(PTQ，便宜)；AWQ 的洞见是”少数重要权重保留高精度”。
  • 剪枝 + 蒸馏 (pruning + distillation)：把大模型里不重要的层/头/维度删掉得到小模型，再用原模型蒸馏修复。
  • 投机采样 (speculative sampling)：用一个便宜的草稿模型先猜几个 token，再用大模型并行检查、接受看着对的。

投机采样为什么不掉精度？ 它用了”检查比生成快”这个不对称：草稿模型快但不准，大模型一次并行检查多个候选 token，并用一种改良的拒绝采样接受/重采。数学上可证明：最终采样结果和直接用大模型逐个生成的分布完全一致——加速但无损。这是本讲最漂亮的点。

应对动态流量（服务系统）

真实在线请求：来的时间不同、长度不同、还常共享前缀（系统提示词）。

  • 连续批处理 (continuous batching)：不等一批人到齐，逐步解码、新请求随到随加入。不同长度的序列在 attention 处分别算、在非 attention 处拼起来算（selective batching）。
  • PagedAttention（vLLM 的招牌）：借操作系统分页的思想，把每条序列的 KV cache 切成不连续的小块，按需分配 → 消除碎片浪费，还能让多条序列共享前缀块（copy-on-write）。

思考练习（多数可纯推理，不需 GPU）

  1. 用一句话解释：为什么推理的 generation 阶段是 memory-bound，而训练是 compute-bound？
  2. 你要服务一个聊天机器人，最在意”用户等第一个字的时间”。该优化 prefill 还是 generation？用大 batch 还是小 batch？
  3. GQA 把 KV cache 缩小，为什么这能直接带来推理提速？（提示：memory-bound）
  4. 用自己的话说清楚：投机采样为什么”又快又不改变输出分布”。

和后续/作业的连接

  • 本讲的算术强度分析直接复用 L02 的方法，是很好的巩固。

检查清单

  • 能解释推理两阶段，以及为什么 generation 是 memory-bound。
  • 能说出 KV cache 是什么、为什么它既是救星又是瓶颈。
  • 能解释”加大 batch 对 MLP 有用、对 attention 没用”的原因。
  • 能说清延迟/吞吐的权衡，以及 prefill/generation 各该用大还是小 batch。
  • 能列出至少三种降 KV cache 的架构，并解释投机采样为何无损。
