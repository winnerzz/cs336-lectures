CS336 学习台

第 7 讲 Parallelism (多 GPU)

预计用时： 120-180 分钟

一句话： 一块 GPU 放不下大模型，或者想训得更快，就得用很多块 GPU。难点不是”算”，而是 GPU 之间怎么搬数据搬得最少。这一讲讲清楚四种切分方式（按数据/宽度/深度/长度切）和它们各自的通信代价。

⚠️ 难度与期待：偏系统，对应 A2，需要多 GPU 才能真跑。零基础先建立”有哪几种并行、各自切什么、代价是什么”的地图即可，具体实现等做 A2。

前置知识：这一讲默认你已经会（我从 0 给你补）

这一讲讲”多台机器/多块卡一起训练”，默认你有一点分布式和操作系统常识。从 0 补上：

  • 进程 (process)：一个独立运行的程序实例，有自己的内存。本讲里每块 GPU 通常由一个进程驱动，进程之间不共享内存，要”通信”才能交换数据。（对比线程 thread：线程在一个进程内、共享内存。）
  • 网络与带宽 (bandwidth)：多台机器靠网线连接，数据在它们之间传输。带宽 = 传输速度（字节/秒），可想成水管粗细。本讲反复比较不同连接(NVLink/Infiniband/以太网)的带宽——这个”带宽=搬数据速度”的直觉其实 L02 就铺过了。
  • 分布式 (distributed)：多台机器协作完成一个任务。难点永远是”怎么少搬数据”——和单卡内少碰 HBM(L05)是同一个主题，只是尺度更大。
  • 梯度 / 参数 / 优化器状态：训练时每块卡上要存的东西，见 L02 的训练显存账。本讲的并行就是在切分这些东西。

先补几个词（零基础向）

  • rank（秩/编号）：每块 GPU 的编号（0、1、2、3…）。
  • world size（总数）：一共有多少块 GPU。
  • collective operation（集合通信）：一组 GPU 之间约定好的群体搬数据动作，比 GPU 两两手动传更快。下面会列。
  • shard（分片）/ replicate（复制）：分片 = 每块 GPU 只存一部分；复制 = 每块都存一份完整的。并行的本质就是在”分片省显存”和”复制省通信”之间权衡。
  • NVLink / Infiniband / Ethernet：GPU 之间的”网线”，从快到慢。同一台机器内的 GPU 用 NVLink（快），跨机器用 Infiniband 或以太网（慢）。
  • NCCL：NVIDIA 的库，把上面的”集合通信”翻译成 GPU 之间真正发的数据包。PyTorch 的 torch.distributed 底层用它。
  • bubble（流水线气泡）：流水线并行里 GPU 闲着等上游的空档，越少越好。

主线和前两讲一脉相承：计算单元离数据很远，一切优化都是为了少搬数据。 单 GPU 内靠 fusion/tiling 少碰 HBM；多 GPU 间靠分片/复制少碰网线。

学完你能

  1. 掌握 7 个集合通信原语，尤其 all-reduce = reduce-scatter + all-gather。
  2. 了解多 GPU 的硬件互联层级（NVLink → Infiniband → Ethernet）和带宽差异。
  3. 理解三种主要并行：数据并行 / 张量并行 / 流水线并行——各切哪个维度、通信代价多大、适合什么网络。

集合通信原语（先认识这几个动作）

设有 4 块 GPU（rank 0–3），每块手里有一小段数据：

操作 干什么 典型用途
Broadcast 把 rank 0 的数据复制给所有人 rank 0 读初始权重，广播给大家
Scatter 把 rank 0 的大数组切片分发 （理解 reduce-scatter 的垫脚石）
Gather 各人的小片收集到 rank 0 （理解 all-gather 的垫脚石）
Reduce 各人的数据求和/取max汇到 rank 0 （理解 all-reduce 的垫脚石）
All-gather 各人的分片收集后发给所有人 每块存一片参数，拼出完整参数做前向
Reduce-scatter 求和后把结果分片存到各人 反向后汇总梯度，但分散存储
All-reduce 求和后所有人都拿到完整结果 反向后汇总梯度，所有人同步
All-to-all 每人给每人发各自一份（最通用） MoE 把数据路由给对应专家

记忆法：Reduce = 做求和这类运算；Scatter 是 Gather 的逆；前缀 All = 结果发给所有人。

最重要的一条等式：all-reduce = reduce-scatter + all-gather。 先各自把梯度求和并分片(reduce-scatter)，再把分片拼回发给所有人(all-gather)。拆开的好处是中间那一步每块 GPU 只存 1/N 的东西——这正是 FSDP/ZeRO 省显存的原理。

硬件互联：越往外越慢

层级 连接方式 带宽量级
单 GPU 内 shared memory ~33 TB/s
单 GPU 内 HBM ~3–8 TB/s
同机器多 GPU NVLink / NVSwitch ~1.8 TB/s
跨机器 Infiniband ~0.05 TB/s
跨数据中心 Ethernet 更慢

典型布局：一台机器 8 块 GPU（NVLink 互联），256 台机器组成一个 pod（Infiniband 互联）。

RDMA 是个关键技巧：让一块 GPU 直接读写另一块 GPU 的显存，绕过 CPU。Infiniband 支持 RDMA，普通以太网不支持（所以慢）。带宽差好几个数量级，决定了”哪种并行能用在哪种网络上”。

三种并行：切的维度不同

回忆 Transformer 里 MLP 是计算主力，所以下面都用”深 MLP”举例。一份激活/数据可以想成 (batch 批量, dim 宽度)，模型有很多 层(深度)。

并行方式 切哪个维度 怎么做 通信代价 适合的网络
数据并行 (Data Parallel) batch（数据） 每块 GPU 拿一片数据、存完整模型，各算各的梯度，再 all-reduce 平均梯度 每步 all-reduce 一次梯度 较省通信，最常用
张量并行 (Tensor Parallel) dim（宽度） 把每一层的权重横着切给各 GPU，每层算完要 all-gather 激活 拼起来 每层都要通信，很频繁 必须很快的网络（NVLink）
流水线并行 (Pipeline Parallel) layer（深度） 每块 GPU 负责连续几层，激活像流水线一样 send/recv 往下传 通信少，但有 bubble 慢网络也能用

三句话记住区别： - 数据并行：模型人手一份，数据分着算，最后对一次梯度。简单、最常用，但模型必须能塞进单卡。 - 张量并行：把一层劈开给几块卡，每层都得拼激活 → 通信极频繁 → 只能用 NVLink。 - 流水线并行：把层分段，像工厂流水线一段传一段 → 通信少 → 慢网络可用，但要用 micro-batch 把流水线填满来减少 bubble（空等）。

DDP vs FSDP/ZeRO（数据并行的两种）：DDP 每块都存完整模型（费显存），用 all-reduce；FSDP/ZeRO 把参数也分片存（省显存），用 all-gather（前向临时拼参数）+ reduce-scatter（反向汇梯度）。后者就是那条等式拆开的应用。

通信带宽怎么测

讲义实测 all-reduce 和 reduce-scatter 的有效带宽，结论： - all-reduce 搬的数据量和耗时都约是 reduce-scatter 的 2 倍 → 两者有效带宽相近（印证了 all-reduce = 两步之和）。 - 有效带宽与 world size、拓扑（环/树）基本无关。
