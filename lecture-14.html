第 14 讲 Data II (过滤/去重/混合)

预计用时： 120-150 分钟

一句话： L13 讲了数据从哪来，这一讲讲怎么加工：转换(HTML→文本)、过滤(挑出好数据)、去重(MinHash/LSH)、混合(各来源配多少比例)，最后是后训练的合成数据。

提示： 难度：概念 + 一点算法（MinHash/LSH 有可运行代码，值得动手）。不太吃 GPU。

前置知识：这一讲默认你已经会（我从 0 给你补）

这一讲会用到”分类器、哈希、集合相似度”。从 0 补上：

  • 分类器 (classifier)：一个给输入打分/分类的小模型。这里用来判断”这段文本是不是高质量/是不是英语/是不是有毒”。常用 fastText（又快又轻）。
  • 哈希函数 (hash)：把任意输入映射成一个固定大小的数字”指纹”。两个不同输入碰巧同指纹叫”碰撞”。加密哈希(SHA-256)防碰撞但慢；MurmurHash 等快但会碰撞，本讲用后者。
  • 集合 (set) 与 Jaccard 相似度：把一段文本看成一堆词的集合 A、B。Jaccard(A,B) = |交集| / |并集|，范围 0~1，衡量两段文本有多像。
  • n-gram：连续 n 个词/字。把文档切成 n-gram 集合，就能用 Jaccard 比相似度。
  • epoch（轮次）：把同一份数据完整过一遍叫一个 epoch。同一数据反复过太多遍会过拟合。

转换 (transformation)：原始数据不是文本

原始数据是 HTML、PDF、代码目录。HTML→文本最常见：要去掉导航/广告这些样板、抽出正文，过程有损（图片表格难保留）。工具：trafilatura、resiliparse、jusText。转换质量直接影响下游模型效果。

过滤 (filtering)：从海量原始数据里挑出”像目标的”

通用框架：给一批目标数据 T（你心目中”好”的样子）和海量原始数据 R，找出 R 里和 T 相似的子集。要求：能泛化、而且极快（要在巨大的 R 上跑）。

两类打分器： - 生成式(KenLM)：score(x) = p_T(x)，T 上训的语言模型给 x 的概率。 - 判别式(fastText 分类器)：score(x) = p(T | x)，直接分类。

应用：① 语言识别（留英语，fastText 支持 176 种语言）；② 质量过滤（如 DCLM 把指令数据当正例、网页当负例训分类器）；③ 毒性过滤（用 Jigsaw 数据训）。

例子 phi-1：“教科书级”高质量小数据训小模型——用 GPT-4 给代码的”教育价值”打分，挑出高分的训。在更少数据上反而更好。

关键洞见（scale-dependent）：没有唯一最优的过滤阈值。 训得久 → 要更多（较低质）数据；训得短 → 要更少（更高质）数据。

去重 (deduplication)：重复数据要删

互联网充满重复（镜像站、GitHub fork、服务条款模板）——C4 里有段产品描述重复了 6 万次。去重的好处：训练更高效、减少记忆（缓解版权/隐私）。

挑战：去重本质是”拿每个文档和其他所有文档比”，必须线性时间才能扩展。

精确去重：对每个文档算哈希，同哈希的只留一个。简单、但抓不到”近似重复”。

近似去重 = MinHash + LSH（本讲精华，有可运行代码）：

  • MinHash：一个神奇的随机哈希，使得 P[minhash(A)=minhash(B)] = Jaccard(A,B)。即两个文档越像，它们的 MinHash 越可能相等。用很多个 MinHash，相等的比例就估计出了 Jaccard 相似度。
  • LSH (局部敏感哈希)：单个 MinHash 太随机。把 n 个 MinHash 分成 b 个”band”、每 band 含 r 个。规则：只要有某个 band 的 r 个哈希全相等，A 和 B 就算碰撞（候选近重复）。这个”band 内全等(and) + 任一 band 命中(or)“的结构，能把”相似度→碰撞概率”的曲线变陡，逼近一个阈值。调 r（变陡、右移）和 b（左移）就能设定”相似度超过多少才算重复”。

运行 lecture_14.py 能看到 MinHash 估计 Jaccard、以及 LSH 碰撞概率随相似度变化的数字。

混合 (data mixing)：各来源配多少比例

模型在多个来源(Wikipedia/网页/代码)上训，比例怎么定？ - 基线：凭感觉(vibes)、均匀、按 token 量正比。 - 直觉是给高质量源更高权重，但有两个坑：① 要保证多样性；② 每个源是有限的，权重太高就得在小源上反复 epoch → 过拟合。

例子：高质量源只有 100 亿 token，你给它 50% 权重训 1 万亿 token → 要 epoch 50 遍 → 过拟合！

解法：UniMax（给每个源的 epoch 数设硬上限 cap）；回归式混合（在小规模试很多配比→拟合”配比→loss”，像缩放定律一样优化最优配比）；模拟 epoching（把小规模实验缩放得像大规模，避免”小规模上看着好、大规模上 epoch 爆炸”）。

后训练数据：合成数据

后训练数据(SFT/RL)的配方：① 定一组环境 ② 定一组任务/提示 ③ 用强模型(teacher)生成回答。

例子：OpenThoughts（用 QwQ-32B 当老师生成 120 万例；有意思的是”更强的模型不一定是更好的老师”）；SWE-smith/SWE-Zero（用 LLM 给真实代码库造 bug/任务，生成大量智能体轨迹）。
