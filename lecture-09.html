第 9 讲 Scaling Laws

预计用时： 120-180 分钟

一句话： 给你一万张 B200 训一个月，你怎么决定训多大的模型、用多少数据、什么超参？缩放定律是答案：在小模型上做实验、拟合一条简单曲线，外推到大模型，从而提前预测大模型的表现和最优配置。

提示： 难度：概念 + 一点统计，不吃 GPU，可纯理解。是 A3 的核心，也是”为什么大家都这么训”的底层逻辑。零基础抓住”小模型预测大模型”这一主线即可。

前置知识：这一讲默认你已经会（我从 0 给你补）

这一讲有点统计味，默认你看得懂”幂律”和”log-log 图”。从 0 把这几样讲明白，正文就顺了：

  • 指数 / 对数 (log)：log 是”取对数”——把很大范围的数压缩到好看的尺度（1、10、100、1000 在 log 轴上是等距的 0、1、2、3）。不用会算，知道”log 让倍数关系变成等距”就够。
  • log-log 图：横轴和纵轴都用 log 刻度的图。本讲最核心的图像：如果 y = x^a（幂律），那么在 log-log 图上它就是一条直线，斜率就是 a。所以”loss 随规模幂律下降”= “在 log-log 图上是一条往下的直线”。
  • 幂律 (power law)：形如 误差 ∝ 1/规模^a 的关系。正文会用一个”估计均值”的小例子从 0 推它为什么出现，看那里即可。
  • 拟合 (fit) 与外推 (extrapolate)：用几个数据点找出那条直线（拟合），再把直线延长去预测没测过的大模型（外推）。这就是缩放定律的全部套路。
  • 6 × 参数量 × token数：计算成本公式，来自 L02。本讲的”计算预算”都建立在它上面。

先补几个词（零基础向）

  • scaling law（缩放定律）：一条简单公式，把”规模”（数据量/参数量/算力）映射到”误差/loss”。
  • power law（幂律）：误差 ∝ 1/规模^α 这种关系。在 log-log 坐标下画出来是一条直线——这是本讲反复出现的关键图像。
  • loss（损失）：衡量模型预测有多差的数字，越小越好。
  • compute-optimal（计算最优）：固定算力预算下，参数量和数据量怎么分配最划算。
  • Chinchilla：一篇著名论文，给出了”每个参数大约配 20 个 token”的计算最优结论。
  • token/参数比：训练用的总 token 数 ÷ 参数量，衡量”训得够不够久”。
  • muP：一种让最优学习率不随模型规模变化的初始化/缩放方法。

学完你能

  1. 理解为什么 loss 和规模在 log-log 上是直线（幂律），以及它的统计直觉。
  2. 理解数据缩放、模型缩放、联合缩放，会用”小模型选超参”的流程。
  3. 搞清 Chinchilla 的”计算最优”，以及为什么实际部署要故意过度训练。

幂律：loss 随规模的直线下降

经验事实：把 test loss 和数据量画在 log-log 坐标上，是一条直线。即 loss ≈ C·n^(−α)（幂律）。这个规律跨领域（翻译、语音、语言建模）、跨模型都成立。

为什么是幂律？一个玩具例子（估计均值）：从 N(μ,σ²) 采 n 个样本估计均值，误差是 σ²/n。取 log：log(误差) = −log(n) + 常数 → 斜率 −1 的直线！这就是最简单的”缩放定律”。任何 1/n^α 的多项式收敛率都是一条缩放定律。 神经网络的 α 和数据的”内在维度”有关（越复杂的数据，下降越慢）。

三类缩放问题

问题 在问什么 用途
数据 vs 性能 多给数据，loss 怎么降 决定要不要多收数据、数据配比
数据 vs 模型大小 该训更大模型还是喂更多数据 资源分配
超参 vs 性能 大模型的超参怎么定 在小模型上选、外推到大模型

数据配比/重复的两个有用结论：① 数据的”成分/质量”主要改变曲线的截距(offset)，不改斜率 → 收集多样、高质量数据很重要。② 数据重复（finite data 反复用）价值递减，effective data 会饱和。

用缩放定律选超参（核心流程）

不必在大模型上瞎调。流程是：

  1. 训几个小模型。
  2. 拟合一条缩放定律（比如 “Adam vs SGD” 的两条曲线、或不同架构）。
  3. 按曲线外推，选出大模型该用的超参。

这样就能在花大钱之前预测：Transformer vs LSTM 谁更好、Adam vs SGD、该多深多宽、batch 多大。

一些具体结论： - 架构/优化器：Transformer 的缩放曲线优于 LSTM；这类选择可在小规模预测。 - 深度 vs 宽度：1 层 vs 2 层差很多，但超过一定深度后收益递减；深宽比有”甜区”。 - 临界 batch size：batch 超过某个临界值后收益递减；loss 目标越低，临界 batch 越大。 - 学习率随规模变：朴素放大模型，最优学习率会变 → 需要 muP 这类”规模感知”的初始化和学习率缩放。 - 注意：上游 loss 可预测，下游任务表现往往没那么可预测。

计算最优：Chinchilla（本讲重点）

联合缩放定律把数据量 n 和模型大小 m 一起建模，比如 误差 ≈ n^(−α) + m^(−β) + C。在固定算力下优化它，就得到”最划算的 (模型大小, 数据量) 组合”。

Kaplan(2020) vs Chinchilla(2022)：早期 Kaplan 认为该把算力更多投在”更大模型”上。Chinchilla 重做实验，结论是 Kaplan 把模型训得太大、数据喂得太少。Chinchilla 的名言：计算最优约为”每个参数配 20 个 token”。（Kaplan 的偏差后来被归因于没数最后一层参数、warmup 设置等细节。）

Chinchilla 用三种方法拟合（都得到相近结论）： 1. 取训练曲线的下包络（所有 run 的最小值连成幂律）。 2. IsoFLOPs：固定几档算力预算，变参数量，取每档最低点连成幂律。 3. 联合拟合：在 (规模, 数据) 网格上跑很多模型，最小二乘拟合联合定律。

关键现实修正：你其实不想要”训练最优”。 Chinchilla 算的是”固定训练算力下最好的模型”。但真实部署里绝大部分算力花在推理上。所以值得故意过度训练（over-train）小模型：参数小→推理便宜，多喂数据→补回性能。看 token/参数比的演变就懂了： - GPT-3：2 tokens/参数 - Chinchilla：20 - LLaMA-65B：22 - Mistral-7B：110 - Llama-3-70B：215

预期用得越多，越值得前期多训。
